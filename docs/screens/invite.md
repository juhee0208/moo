# 화면: 초대 링크 진입 · 초대장

관련 정책: `02-policies.md` 7절(초대), 8.2절(삭제된 그룹)

## 1. 초대 링크 진입 처리

카카오톡 메시지의 버튼을 누르면 앱이 실행되고, 앱 실행 파라미터로 토큰이 전달된다. 미설치 시 카카오가 App Store로 보내고, 설치 · 로그인 후 **메시지를 다시 눌러야** 이 처리로 들어온다(지연 딥링크 없음, D55). Android · PC 카톡에서는 블로그 iOS 안내 글이 열린다(D71). 앱에서는 **로그인 여부와 상관없이** 아래 순서로 판단한다.

| 순서 | 링크 / 그룹 상태 | 처리 |
|---|---|---|
| 1 | 그룹 삭제됨 | `MOOHAPP_TOAST_GROUP_DELETED` → 현재 화면 유지, 앱 첫 진입이면 홈 (비로그인은 온보딩/로그인) (`02-policies.md` 8.2) |
| 2 | 만료 (`EXPIRED`) | `MOOHAPP_DIALOG_INVITE_EXPIRED` → [확인] → 홈 (비로그인은 온보딩/로그인) |
| 3 | 재발급으로 무효 (`DISABLED`) 또는 알 수 없는 토큰 (D72) | `MOOHAPP_DIALOG_INVITE_DISABLED` → [확인] → 홈 (비로그인은 온보딩/로그인) |
| 4 | 이미 멤버 / 본인 그룹 | 초대장 없이 그룹 상세로 |
| 5 | 유효 + **로그인** | 대기 초대 목록에 추가 → `mooh: 초대장` 열기 (2절) |
| 6 | 유효 + **비로그인** | `비밀 초대장` 열기 (3절) |

- 판정 순서는 `07-dev-design.md` 7.4와 같다. 삭제된 그룹의 만료 링크는 "삭제된 그룹"으로 안내
- 정원(기본 20명)과 내 그룹 수(기본 5개)는 링크 진입 시가 아니라 **참여 확정 시점**에 검증

## 2. mooh: 초대장 — `MOOHAPP_INVITE_INBOX` (풀팝업, 로그인 사용자 전용)

받은 초대를 **그룹별 리스트로 모두 모아** 보여준다. 링크로 들어와도 그 그룹 1건만이 아니라 현재 대기 중인 모든 초대를 같이 보여준다. **비로그인 사용자에게는 노출하지 않는다** (비로그인은 3절 `비밀 초대장`).

### 2.1. 화면

```text
+-----------------------------------+
|             mooh: 초대장       [X] |
|          [MOOH 초대 캐릭터]         |
|   도착한 초대 {n}개                |
| [커버] 데이트 코스          (v)   |
|        {생성자}님의 그룹          |
|        멤버 3 · 맛집 23           |
| [커버] 회사 근처            ( )   |
|        {생성자}님의 그룹          |
|        멤버 8 · 맛집 41           |
| [휴지통]  [  그룹 참여하기 (1)  ] |
+-----------------------------------+
```

| 영역 | 동작 |
|---|---|
| 초대 정보 | 헤더 `도착한 초대 {n}개` + 캐릭터 (D75) |
| 그룹 리스트 | 커버, 그룹명, `{생성자}님의 그룹`(초대자 = 생성자, D42 · D75), 멤버 수·맛집 수, 체크. 링크로 들어온 그룹은 기본 체크 |
| 휴지통 | 선택한 초대 삭제(거절) → `MOOHAPP_DIALOG_INVITE_REJECT_CONFIRM` |
| CTA | `[그룹 참여하기 (n)]` 선택 수 표시, 0개면 비활성 |

- 참여 확정 시 그룹마다 재검증: 그룹 상태, 링크 상태, 정원, 내 그룹 수(상한 도달 이후 그룹은 실패)
- 결과 (D74)
  - 1개 성공 → 그 그룹 상세 / 2개 이상 성공 → 그룹 홈
  - 일부 실패 → 이동 후 `MOOHAPP_TOAST_INVITE_JOIN_PARTIAL` 한 번
  - 전부 실패 → 초대장 유지 + `MOOHAPP_TOAST_INVITE_JOIN_FAIL`. 1개만 선택했으면 해당 코드의 Dialog(`GROUP_MEMBER_LIMIT` / `GROUP_LIMIT` 등)
- 삭제된 그룹의 초대, 링크가 만료·무효된 초대는 목록에서 자동 제외 (D43)
- 0건 → 빈 화면 문구

## 3. 비밀 초대장 — `MOOHAPP_INVITE_PREVIEW` (비로그인 전용)

친구 초대 화면(`group.md` 5절 `MOOHAPP_GROUP_INVITE`)과 같은 레이아웃을 쓰고 아래만 다르다.

| | 친구 초대 (`GROUP_INVITE`) | 비밀 초대장 (`INVITE_PREVIEW`) |
|---|---|---|
| 상단 타이틀 | 친구 초대 | **비밀 초대장** |
| 초대 링크 영역 | 유효기간 + `[새 링크 만들기]` | **없음** (초대받은 사람에게 불필요) |
| 멤버 `나` 표시 | 있음 | **없음** (보는 사람은 아직 멤버가 아님) |
| 하단 CTA | 카카오톡으로 공유하기 | **그룹 참여하기** |

```text
+-----------------------------------+
|            비밀 초대장         [X] |
|          [그룹 커버]              |
|             데이트 코스           |
|     을지로, 종로 일대 맛집 모음   |
|        [멤버 7] [맛집 23]         |
| --------------------------------- |
| 현재 멤버                         |
| (프로필)   (프로필)   (프로필) -> |
| {닉네임}   {닉네임}   {닉네임}    |
| 생성자     멤버       멤버        |
|                                   |
| [          그룹 참여하기         ]|
+-----------------------------------+
```

| 영역 | 구성 | 동작 |
|---|---|---|
| 헤더 | 타이틀 `비밀 초대장`, `[X]` | `[X]` → 일반 진입 흐름 (온보딩 또는 로그인) |
| 그룹 요약 | 커버, 그룹명, 설명, `멤버 N` · `맛집 N` 칩 | 링크로 들어온 그룹 1건만 |
| 현재 멤버 | 프로필, 닉네임, 역할(생성자/멤버) | 가로 스크롤. `나` 표시 없음, 생성자는 맨 앞. 비로그인에게 멤버 공개 OK (D31) |
| 하단 CTA | `[그룹 참여하기]` | → 로그인 (신규면 약관까지) → 로그인 완료 후 **이 그룹 참여 처리** → 그룹 상세 |

- 로그인 후 참여 직전 검증(그룹 상태, 링크 상태, 정원, 내 그룹 수). 실패 시 해당 Dialog → 홈
- 로그인했는데 이미 멤버였다면 참여 처리 없이 그룹 상세
- 로그인 도중 이탈(취소)하면 참여하지 않음. 링크를 다시 열면 이 화면부터

## 4. 초대장 여는 곳

| 진입 경로 | 비고 |
|---|---|
| 초대 링크 | 1절. 로그인 → mooh: 초대장 / 비로그인 → 비밀 초대장 |
| 마이 > `mooh: 초대장` 진입점 | 대기 초대 전체 확인 |

- 앱 실행 시 자동으로 열지 않는다. 대기 초대가 있으면 하단 마이 탭에 점, 마이 `mooh: 초대장` 메뉴에 개수 (D76)
