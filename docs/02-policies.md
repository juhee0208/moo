# 02. 정책 · 권한 · 상태값

이 문서의 수치와 정책이 화면 문서보다 우선합니다.

## 1. 정책 수치 (상수로 관리)

코드에서는 아래 상수명(예시)으로 관리하고 하드코딩하지 않는다. 그룹 수·그룹당 맛집 수·그룹당 멤버 수는 **요금제별로 덮어쓸 수 있게** 설계한다(D34, `07-dev-design.md` 2절). 아래 값은 무료(FREE) 기본값이다.

| 상수 (예시) | 값 | 설명 |
|---|---|---|
| `MAX_GROUPS_PER_USER` | 5 | 사용자당 그룹 수. **만든 그룹 + 참여한 그룹 합계** (D32) |
| `MAX_PLACES_PER_GROUP` | 100 | 그룹당 맛집 수 (D33) |
| `MAX_MEMBERS_PER_GROUP` | 20 | 그룹당 멤버 수 (생성자 포함). 그룹 관련 상한은 생성자의 요금제 기준 |
| `GROUP_NAME_MAX_LENGTH` | 15 | 그룹명, 띄어쓰기 포함 |
| `GROUP_DESC_MAX_LENGTH` | 15 | 그룹 설명, 띄어쓰기 포함 |
| `INVITE_LINK_TTL_DAYS` | 3 | 초대 링크 유효기간 (발행 시점부터) |
| `RECENT_SEARCH_MAX` | 10 | 최근 검색어 |
| `HOME_RECENT_GROUPS_MAX` | 5 | 홈 최근 그룹 |
| `HOME_RECENT_PLACES_MAX` | 5 | 홈 최근 저장 맛집 |
| `HOME_FRIENDS_MAX` | 6 | 홈 함께하는 친구 |
| `SHARED_BADGE_MIN_MEMBERS` | 2 | 멤버가 이 수 이상이면 '공유' 배지 |
| `NICKNAME_MIN_LENGTH` / `NICKNAME_MAX_LENGTH` | 2 / 10 | 닉네임 (D81) |
| `NOTIFICATION_RETENTION_DAYS` | 90 | 알림함 보관 기간 (D83) |
| `NOTIFICATION_MAX_PER_USER` | 100 | 사용자당 알림 최대 개수 (D83) |
| `UPLOAD_MAX_MB` | 10 | 커버 · 프로필 이미지 업로드 (D68) |
| `IMAGE_MAX_EDGE_PX` | 1080 | 서버 재인코딩 긴 변 (D68) |

## 2. 핵심 원칙

- 한 맛집은 **여러 그룹에 중복 저장 가능**
- **같은 그룹 안에서는 같은 맛집 중복 저장 불가** (`group_id + place_id` 유일)
- 모든 그룹은 **비공개(초대제)**. 공개 그룹 없음
- 생성자 **소유권 이전 없음**
- **푸시 알림 없음.** 비동기 안내는 알림함(`screens/my.md`)으로만 전달

## 4. 앱 권한

- 앱은 **권한을 요청하지 않는다** — 위치 · 알림 · 사진 팝업 없음. 사진은 iOS PhotosPicker라 권한이 필요 없다 (D54)
- **위치 정보를 수집하지 않는다.** 위치 권한 · 위치기반서비스 약관 · 내주변 지도 없음 (D66)
- 업로드 이미지(커버 · 프로필)는 서버가 긴 변 1080px JPEG로 재인코딩하고 **EXIF(GPS 포함)를 제거**한다. 10MB 이하 JPEG · PNG · HEIC (D68)

| 항목 | 정책 |

| 항목 | 정책 |
|---|---|

| 내보내기 후 재발급 | 멤버 내보내기 직후 링크 자동 재발급. 기존 링크로 쌓인 대기 초대도 함께 제외 (D73) |
| 공유 | **생성자만** 가능. 멤버에게는 링크·공유 진입점을 노출하지 않음 (D40) |
| 초대자 표시 | 초대장의 초대자는 항상 **생성자** (D42) |
| 대기 초대 | 로그인 사용자가 링크로 진입한 초대는 초대장(대기 초대 목록)에 쌓임. 참여·거절(삭제) 전까지 유지하되 **링크에 종속**: 링크가 만료·무효가 되면 목록에서 자동 제외 (D43) |
| 초대장 자동 노출 | 없음. 대기 초대가 있으면 하단 마이 탭 점 · 마이 `mooh: 초대장` 개수 (D76) |
| 공유 방식 · 앱 미설치 | **카카오톡 공유로만** (D55). 앱 있으면 메시지 버튼으로 앱 실행 → resolve. 앱 없으면 카카오가 App Store로 이동 → 설치 · 로그인 후 **메시지를 다시 눌러** 참여. 지연 딥링크 · 랜딩 페이지 없음. Android · PC 카톡은 메시지 버튼의 웹 링크로 블로그 iOS 안내 글 (D71) |
| 비로그인 진입 | `mooh: 초대장`은 로그인 사용자 전용. 비로그인은 `비밀 초대장`(그룹 1건 미리보기) → [그룹 참여하기] → 로그인 후 바로 참여 |
| 정원 | 멤버 20명 도달 그룹은 참여 불가 |
| 이미 멤버 | 초대 화면 생략, 그룹 상세로 이동 |
| 본인 그룹 링크 | 초대 화면 생략, 그룹 상세로 이동 |
| 만료/무효 링크 | 초대장 진입 전 Dialog로 차단 → [확인] 시 홈 이동. 알 수 없는 토큰도 무효로 안내 (D72) |
| 삭제된 그룹 링크 | Toast 후 현재 화면 유지 (8절) |
| 참여 직전 검증 | 그룹 상태, 링크 상태, 그룹 멤버 수, 내 그룹 수를 다시 검증 |

## 8. 삭제 · 탈퇴 · 강퇴

### 8.1. 그룹 삭제 (생성자 직접 삭제 / 생성자 회원 탈퇴 — 동일 처리)

- 생성자만 가능. 직접 삭제는 확인 Dialog 필수
- 삭제 즉시 모든 멤버의 그룹 목록·홈 최근 그룹·초대장에서 제거, 연결된 초대 링크 즉시 무효
- 다른 그룹에 저장된 같은 맛집은 유지
- 생성자: 성공 Toast·완료 화면 없이 그룹 홈으로 이동
- 남은 멤버: **모달·푸시 없이 알림함에만 항목 추가.** 문구는 삭제 사유를 변수로 처리 (`05-messages.md` 알림함 문구)

### 8.2. 삭제된 그룹에 접근할 때

| 경로 | 처리 |
|---|---|
| 초대장에 남아 있던 초대 | 목록에서 자동 제외 (보이지 않음) |
| 예전 초대 링크 / 딥링크 | Toast `삭제된 그룹이에요.` → 현재 화면 유지 (앱 첫 진입이면 홈) |
| 갱신 전 화면에 남은 카드 터치 | Toast → 현재 화면 유지, 목록 갱신 |
| 그룹 상세를 보고 있는 중 삭제됨 | 다음 데이터 갱신 시 Toast → 이전 화면으로 복귀 |

### 8.3. 멤버 내보내기(강퇴)

- 생성자만 가능, 본인 제외, 확인 Dialog 후 처리
- 내보내진 멤버는 즉시 그룹 접근·편집 차단
- 해당 멤버에게 **알림함에만** 항목 추가 (모달 없음)
- 처리 직전 대상이 아직 멤버인지 재검증. 이미 나갔으면 목록만 갱신
- 처리 후 초대 링크 자동 재발급 (D73)

### 8.4. 그룹 나가기

- 일반 멤버만 가능, 확인 Dialog 후 처리. 생성자는 나가기 대신 삭제

### 8.5. 회원 탈퇴

- 환경설정 > 회원 탈퇴 (설정 진입 후 1단계 이내 — 앱스토어 심사 기준)
- 탈퇴 시 개인 데이터 지체 없이 파기 (개인정보보호법)
- 탈퇴 확인 Dialog 후 **가입한 provider로 재로그인** → 받은 토큰으로 **Apple 토큰 revoke + 카카오 · 네이버 · Google 연결 끊기** (D61 · D82). provider 토큰은 평소에 저장하지 않는다
- 재로그인 취소 → 탈퇴 취소. 가입한 계정과 다른 계정 → `MOOHAPP_DIALOG_WITHDRAW_REAUTH_MISMATCH`
- 연결 끊기가 실패해도 파기는 진행. 요청 안에서 재시도하고, 그래도 실패하면 개인정보 없이 실패 건만 기록
- 내가 만든 그룹은 **자동 삭제** (8.1과 동일하게 남은 멤버 알림함 안내)
- 내가 참여한 그룹에서는 자동으로 빠짐
- 탈퇴 확인 Dialog에서 함께 삭제되는 그룹 수 안내
- 복구 불가

### 9.1. 폐업 맛집 자동 삭제 방식

- 그룹 상세 진입 시, 화면에 불러오는 그룹 맛집을 카카오 API로 재조회 (목록 표시를 위해 어차피 필요한 호출)
- 재조회에서 저장된 장소 ID가 확인되지 않으면 `미확인 1회`로 기록
- **연속 2회 미확인**(서로 다른 날) 시 그룹에서 자동 삭제 → 상호 변경·일시적 검색 누락으로 인한 오삭제 방지
- 같은 맛집 확인은 **하루 1회까지** (서버에 마지막 확인 시각 기록 — 자체 데이터라 저장 가능)
- 목록은 한 번에 20개씩 불러오고, 스크롤로 더 불러올 때 그만큼만 확인 (전체를 한 번에 호출하지 않음)
- **자동 삭제는 기능 플래그(`place_auto_remove_enabled`)로 제어하며 기본 off.** 좌표 기반 재조회가 가능해질 때까지는 미확인 맛집을 그 화면에서 숨기기만 하고 상태는 바꾸지 않는다 (D36)
- 카카오 호출 자체가 실패(타임아웃·429·5xx)한 경우는 미확인으로 세지 않는다
- 그룹 맛집 개수 표시(`N/100`)는 숨긴 맛집을 포함한 서버 저장 수 기준 (D37)
- 자동 삭제 시 그 그룹의 **멤버 전원 알림함**에 안내 (`NOTI_PLACE_AUTO_REMOVED`, D56)

| | `GROUP_DELETED` | 그룹 삭제로 무효 |
| 대기 초대 | `PENDING` / `JOINED` / `REJECTED` | 초대장 목록 상태 |
| 그룹 맛집 | `ACTIVE` | 정상 |
| | `MISSING_1` | 재조회 미확인 1회 |
| | (삭제) | 연속 2회 미확인 시 연결 삭제 |
| 알림 | `UNREAD` / `READ` | 알림함. 90일 또는 최근 100개 초과분 정리 (D83) |

## 11. 동시성

- 맛집 저장은 `group_id + place_id` 기준 중복 생성 차단. 동시 추가 시 첫 요청만 유지, 이후 요청엔 최신 상태 반환
- 이미 삭제된 그룹 맛집을 다시 삭제하면 오류 없이 목록만 갱신
- 그룹 삭제·멤버 내보내기·초대 참여 직전 권한과 상태 재검증
- 화면 진입, 앱 포그라운드 복귀, 저장·삭제 완료 시 최신 데이터 재조회

## 12. 네트워크 · 오류 공통

- 조회 실패: 기존 데이터 유지 + 재시도
- 생성·수정·삭제 실패: 성공으로 처리하지 않고 이전 상태 복원
- 오프라인 상태의 저장·삭제·그룹 생성 미지원
- 다중 그룹 저장 중 일부 실패: 성공한 그룹은 유지, 실패한 그룹만 재시도
