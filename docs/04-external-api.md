# 04. 외부 API — 카카오 지도 / 로컬

⚠️ 카카오 관련 코드를 작성할 때마다 이 문서를 다시 확인할 것.

## 1. 사용하는 API (확정)

| 용도 | API |
|---|---|
| 지도 표시, 마커 | 카카오맵 SDK (iOS / Android) |
| 키워드 검색 (상호명·지역·역명·주소) | 카카오 로컬 API — 키워드로 장소 검색 |
| 길찾기 | 카카오맵 앱 URL Scheme / 웹 |

네이버는 사용하지 않는다. 네이버 지역검색 API는 한 번에 최대 5개 결과, 좌표·반경 검색 불가, 장소 ID 없음 → 그룹 저장 구조(장소 ID 저장 · 재조회)에 맞지 않음 (`decisions.md`).

## 2. 받을 수 있는 데이터

카카오 로컬 API 응답 필드:

`id`, `place_name`, `category_name`, `category_group_code`, `category_group_name`, `phone`, `address_name`, `road_address_name`, `x`(경도), `y`(위도), `place_url`, `distance`

- **받을 수 없는 것: 사진, 영업시간, 주차 등 상세 정보** → 화면에서 사용하지 않는다
- 한 페이지 최대 15개, 페이지를 넘겨도 **최대 45개**
- 반경 검색은 최대 20km
- `road_address_name`은 빈 값일 수 있음 → `address_name`으로 대체
- 무료 쿼터 초과 시 429 에러 → 공통 에러 처리 + 재시도

## 3. 저장 규칙 — 반드시 지킬 것

카카오 로컬 API 응답은 **실시간 호출 용도로만** 사용한다. 로컬 API는 **서버에서만 호출**하고(REST 키를 앱에 넣지 않음), 서버는 응답을 저장·캐싱하지 않고 바로 반환한다 (`07-dev-design.md` 1절).

| 데이터 | 우리 DB 저장 |
|---|---|
| 장소 ID (`id`) | ✅ 저장 |
| `place_url` | ✅ 저장 (ID로 만들 수도 있음) |
| 장소명 (`place_name`) | ✅ 저장 — 사용자가 저장 시점에 확인한 이름 |
| 좌표 (`x`, `y`) | ⚠️ `TODO` 카카오 확인 전까지 저장하지 않음 (`open-questions.md`). 허용 시 `place_coords_enabled` on (D35, D39) |
| 주소, 전화번호, 카테고리 | ❌ 저장 금지. 조회 시점에 재호출 |
| 검색 결과 목록, 응답 원문 | ❌ 저장·캐싱 금지 |

- 우리 서비스가 만든 데이터(그룹, 저장 시각, 저장한 사람, 마지막 확인 시각, 미확인 횟수 등)는 자유롭게 저장 가능
- 이 규칙과 다른 방식이 필요해 보이면 구현하지 말고 먼저 사용자에게 확인

## 4. 화면별 호출 방식

| 화면 | 호출 |
|---|---|
| 통합 검색 | 키워드 검색. 디바운스 적용, 공백만 입력 시 호출 안 함 |
| 맛집 상세 | 검색에서 진입: 이미 받은 결과를 화면 인자로 전달(추가 호출 없음). 저장된 맛집에서 진입: 저장된 장소명(좌표 저장 허용 시 + 좌표)으로 키워드 검색 → 같은 `id`를 찾아 표시. 못 찾으면 `MOOHAPP_TOAST_PLACE_LOAD_FAIL` → 이전 화면 |
| 그룹 상세 맛집 탭 | 화면에 불러오는 20개씩 재조회. 동시에 폐업 확인 (`02-policies.md` 9.1) |
| 홈 최근 저장 맛집 | 최대 5개 재조회 |

참고: 카카오에는 **장소 ID로 바로 조회하는 API가 없다.** 이름으로 다시 검색해 같은 ID를 찾아야 하므로 체인점처럼 같은 이름이 많으면 45개 안에 안 나올 수 있다. 정확도를 위해 위치 기준 검색이 필요하고, 이것이 좌표 저장 확인(`TODO`)이 중요한 이유다.

## 5. 금지 사항

- 카카오맵 장소 페이지(`place_url`)의 내용을 프로그램으로 읽어 오는 것(크롤링) 금지 — 약관 위반, 키 차단 위험
- `place_url`은 사용자가 버튼을 눌러 카카오맵 앱/웹으로 **이동**하는 용도로만 사용

## 6. 개발 착수 전 할 일 — **선행 조건** (D35)

- 카카오 데브톡에 MOOH 구조(그룹 저장, 장소 ID·장소명 저장, 재조회 방식)를 설명하고 이용 정책 확인 (약관은 수시로 바뀜)
- 무료 쿼터와 예상 호출량(그룹 상세 진입 × 20건) 비교
